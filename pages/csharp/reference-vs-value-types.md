## この記事でわかること

- 変数を代入したときに「値がコピーされる型」と「同じ実体を指すようになる型」の違いが説明できる
- 参照型のインスタンスをメソッドに渡すと、呼び出し元にも変更が反映される理由が説明できる
- ヒープとスタックという言葉が指すものを、それぞれ説明できる

## 一言でいうと

値型の変数は値そのものを持ち、代入するとコピーが作られて別々のものになります。参照型の変数は「実体がどこにあるか」という場所の情報だけを持ち、代入すると同じ実体を指すようになります。

友達に写真を渡す場面を考えてみてください。写真を印刷してコピーを渡せば、それはもうあなたの写真とは別物です。相手が落書きしても、あなたの写真はきれいなままです。一方、写真がクラウドに保存されていて、そのリンクだけを送ったとします。この場合、あなたと相手は同じ1枚の写真を見ていることになり、相手が編集すればあなたの画面でもその写真は変わります。プログラムの世界では、`int`や`bool`のような値型の変数を代入するとき、写真をコピーして渡すのと同じことが起きます。`class`で作った参照型の変数を代入するときは、共有リンクを渡すのと同じことが起きます。ただし、実際のリンクとは違って、参照型の変数がやり取りしているのは「メモリ上のどこにデータがあるか」という住所のような情報です。

## どんなときに困るのか

新人のうちによくあるのが、こんな失敗です。`Product`のインスタンスを別の変数に代入して、片方だけを書き換えたつもりが、なぜかもう片方の値まで変わってしまう。逆に、メソッドの引数に`int`を渡して中で値を増やしたのに、呼び出し元では変わっていない。どちらも「代入したら何が起きるか」を型ごとに正しく理解していないと再現できず、原因を探すのに時間がかかります。先輩に「それは参照型だから」と言われても、参照型が何かわからなければ納得もできません。

この違いを理解していれば、複数の変数が同じデータを共有しているのか、それぞれ独立したコピーを持っているのかを最初から見通せるようになります。バグを踏む前に、意図した挙動になる書き方を選べます。

## 動かしてみる

```csharp
var a = 10;
var b = a;
b = 20;
Console.WriteLine(a);
Console.WriteLine(b);
```

```
10
20
```

`b = a`の時点で、`a`が持っていた値10が`b`にコピーされます。その後`b`に20を代入しても、それは`b`という変数の中身を書き換えているだけなので、`a`の値には影響しません。`a`と`b`は代入した瞬間から別々の実体になっています。

## 仕組み

`int`や`bool`、`double`のような型は値型と呼ばれます。値型の変数は、値そのものを直接持っています。先ほどの例で`b = a`と書いたとき、10という値そのものが`a`から`b`にコピーされました。だから`b`を変えても`a`は変わりません。

一方、`class`で作った型は参照型と呼ばれます。参照型の変数が持っているのは実体そのものではなく、実体が置かれている場所の情報です。これを参照と呼びます。次のコードで確かめてみましょう。

```csharp
var p1 = new Product { Name = "ノート", Price = 100 };
var p2 = p1;
p2.Price = 200;
Console.WriteLine(p1.Price);
Console.WriteLine(p2.Price);

public class Product
{
    public string Name = "";
    public int Price;
}
```

```
200
200
```

`p2 = p1`と書いたとき、コピーされたのは`Product`の実体ではなく、「その実体がどこにあるか」という参照です。つまり`p1`と`p2`はどちらも同じ1つの`Product`インスタンスを指しています。だから`p2.Price`を書き換えると、同じ実体を見ている`p1.Price`も200になります。

`new`で作られた`Product`の実体は、ヒープと呼ばれる領域に置かれます。ヒープは、実体を保管しておく共有の倉庫のようなものだとイメージしてください。参照型の変数は、その倉庫の中のどこに実体があるかという住所だけを持ちます。倉庫に置かれた実体は、それを指す変数が1つでも残っている間は片付けられません。誰からも参照されなくなった頃に、GC(ガベージコレクタ。使われなくなった実体を見つけて自動的に片付けてくれる仕組み)が回収します。

値型の変数は、多くの場合スタックと呼ばれる場所に置かれます。スタックは、メソッドを実行している間だけ使う作業机のようなものです。メソッドの実行が終わると、その机の上のものはまとめて片付けられます。ただし、厳密には値型の変数がクラスのフィールドとして持たれている場合、その値型もヒープ上の実体の一部として置かれます。「値型は必ずスタックに乗る」というのは正確ではなく、まずは「値そのものを持つか、場所の情報を持つかという違い」で覚えておけば困りません。値型を自分で定義する`struct`という仕組みは、次の記事で扱います。

- 値型の変数は値そのものを持ち、代入や引数渡しのたびにコピーされる
- 参照型の変数は実体の場所(参照)を持ち、代入や引数渡しでは参照だけがコピーされる。実体は増えない
- 参照型の実体は`new`のたびにヒープに置かれ、GCが不要になったものを回収する
- 値型は基本的にスタックに置かれるが、クラスのフィールドになっている場合はヒープ上の実体の一部になる

## 実務での使い方

参照型が「同じ実体を共有する」性質は、意図的に使われることがよくあります。次の例は、注文の合計金額をメソッドの中で書き換えて、呼び出し元にもその変更を反映させています。

```csharp
var order = new Order { Total = 1000 };
ApplyDiscount(order);
Console.WriteLine(order.Total);

void ApplyDiscount(Order order)
{
    order.Total -= 100;
}

public class Order
{
    public int Total;
}
```

```
900
```

`ApplyDiscount`に渡された`order`は、呼び出し元の`order`と同じ実体を指しています。だからメソッドの中で`Total`を書き換えると、呼び出し元で読み取る`Total`も900になります。これは参照型ならではの挙動で、状態を持つデータを複数箇所から更新したいときによく使われます。

- 複数箇所から同じデータを共有し、変更を伝え合いたい → 参照型(`class`)
- 独立したコピーとして安全に扱いたい小さな値(数値・真偽値など) → 値型(`int`、`bool`、`double`のような組み込みの値型。自分で値型を定義したい場合は`struct`を使いますが、これは次の記事で扱います)

## よくある間違い

### 参照型を代入すれば独立したコピーができると思い込む

`class`のインスタンスを別の変数に代入したとき、それぞれ別の実体になったと思い込んでしまう間違いです。実際には参照がコピーされるだけなので、片方を書き換えるともう片方にも影響します。

```csharp
// NG: p2への代入でp1とは別の実体ができたと思い込む
var p1 = new Point { X = 1, Y = 1 };
var p2 = p1;
p2.X = 99;
Console.WriteLine(p1.X);

public class Point
{
    public int X;
    public int Y;
}
```

```
99
```

```csharp
// OK: 独立したコピーが欲しいなら、新しい実体を自分でnewする
var p1 = new Point { X = 1, Y = 1 };
var p2 = new Point { X = p1.X, Y = p1.Y };
p2.X = 99;
Console.WriteLine(p1.X);
```

```
1
```

### 値型をメソッドに渡せば呼び出し元も書き換わると思い込む

逆のパターンもよくある間違いです。`int`のような値型をメソッドの引数に渡して中で書き換えても、渡したのは値のコピーなので、呼び出し元の変数はそのまま変わりません。

```csharp
// NG: メソッドの中でnumberを増やせば呼び出し元も変わると思い込む
void Increment(int number)
{
    number++;
}

var count = 10;
Increment(count);
Console.WriteLine(count);
```

```
10
```

```csharp
// OK: 呼び出し元の値を更新したいなら、新しい値を返して代入し直す
int Increment(int number) => number + 1;

var count = 10;
count = Increment(count);
Console.WriteLine(count);
```

```
11
```

## 注意点

参照型のインスタンスをループの中で大量に`new`すると、ヒープへの確保とGCによる回収が増え続け、アプリの動作が遅くなることがあります。座標や金額のような小さな値をそのたびに`class`でnewしていないか、見直す価値があります。次の記事で扱う`struct`を使うと、値型として実体を直接持てるので、ヒープへの確保を減らせる場合があります。

## 用語まとめ

| 用語 | 意味 |
|---|---|
| 値型 | 変数が値そのものを持ち、代入時にコピーされる型。`int`、`bool`、`double`など |
| 参照型 | 変数が実体の場所(参照)を持ち、代入時には参照がコピーされる型。`class`で作った型など |
| 参照 | 実体が置かれている場所を示す情報。参照型の変数が持っている中身 |
| 実体 | `new`によって実際に作られたデータそのもの |
| ヒープ | `new`で作られた実体が置かれる共有の領域 |
| スタック | メソッドの実行中だけ使われる、値型の変数などが置かれる作業領域 |
| GC(ガベージコレクタ) | ヒープ上の使われなくなった実体を見つけて自動的に片付ける仕組み |
