## この記事でわかること

- クラスを定義して、インスタンスを作れる
- フィールド・プロパティ・コンストラクタの役割の違いを説明できる
- コンストラクタを使って、初期化を強制するクラスを書ける
- クラスの変数を別の変数に代入したときに何が起きるかを説明できる

## 一言でいうと

クラスとは、いくつかのデータとそれを扱う処理をひとつにまとめて、名前を付けたものです。

料理のレシピを思い浮かべてください。レシピには材料と作り方が書いてありますが、レシピの紙自体は食べられません。実際に材料を集めて作った料理だけが、皿に盛られて食べられる形になります。プログラムの世界では、レシピにあたるのがクラスで、それをもとに実際に作ったものにあたるのがインスタンスです。クラスを`new`というキーワードとともに書くことで、初めてデータを持ったインスタンスができあがります。ただし実際のレシピと違い、同じクラスから作った複数のインスタンスは、それぞれ別のデータを持てます。

## どんなときに困るのか

商品の注文処理を書くとき、商品名・価格・数量をそれぞれ別の変数として持ち歩いていると、困ったことが起きます。合計金額を計算するメソッドに商品名・価格・数量を1つずつ引数で渡していくうちに、渡す順番を間違えて、価格の欄に数量を渡してしまうようなミスが起きやすくなります。メソッドが増えるたびに同じ引数の並びをコピーして書くことになり、1か所を直し忘れて金額がずれる、というバグにもつながります。

商品名・価格・数量のようにセットで扱うデータをクラスにまとめておけば、メソッドには「商品」という1つのかたまりを渡すだけで済み、順番を間違える心配がなくなります。

## 動かしてみる

商品を表すクラスを作り、インスタンス化して値を出力してみます。

```csharp
var product = new Product();
product.Name = "コーヒー";
product.Price = 480;
Console.WriteLine(product.Name);

public class Product
{
    public string Name = "";
    public decimal Price;
}
```

```
コーヒー
```

`public class Product`の中に書いた`Name`と`Price`は、`Product`が持つデータの置き場所で、フィールドと呼びます。この時点では`Product`という設計図があるだけで、実際に使えるデータはまだ何もありません。`new Product()`と書いたところで、初めて`Name`と`Price`を持った実体ができあがります。この実体をインスタンスと呼び、`product`という変数にはそのインスタンスが入ります。あとは`product.Name`のようにドットでつなげて、フィールドに値を代入したり、読み出したりできます。

## 仕組み

`new Product()`を実行すると、`Product`というクラスの形にしたがって、`Name`と`Price`を持つインスタンスが1つ作られます。同じクラスから`new`をもう一度実行すれば、まったく別のインスタンスができ、それぞれが自分のフィールドの値を持ちます。

クラスの変数を別の変数に代入したときの挙動には、少し注意が必要です。`var b = a;`と書いても、`a`の中身がまるごとコピーされて`b`に入るわけではありません。実際には、`a`が指しているのと同じインスタンスを、`b`という名前でも指すようになるだけです。そのため、`b`のフィールドを書き換えると、同じインスタンスを見ている`a`側からも、変更後の値が見えます。この話は「参照と値の違い」というテーマそのものなので、詳しくは次の記事に譲りますが、ここでは「クラスの変数を代入しても中身はコピーされず、同じものを2つの名前で指すだけ」という点だけ覚えておいてください。

もう1つ覚えておきたいのが、初期化を担当するコンストラクタです。コンストラクタとは、`new`でインスタンスを作るときに自動的に呼ばれる、初期化専用の処理です。コンストラクタを自分で書かなかった場合でも、C#は何もしない引数なしのコンストラクタを自動的に用意してくれるので、`new Product()`のように書けます。

- クラスを定義しただけでは何も作られない。`new`を書いて初めてインスタンスができる
- 同じクラスから作った複数のインスタンスは、それぞれ別のデータを持つ
- クラスの変数を別の変数に代入しても、データはコピーされず、同じインスタンスを2つの名前で指すようになる
- コンストラクタを書かなければ、何もしない引数なしのコンストラクタが自動的に用意される

## 実務での使い方

実務のコードでは、フィールドに直接値を代入させず、コンストラクタで初期化を強制する書き方がよく使われます。値の置き場所には、フィールドではなくプロパティ(`{ get; set; }`)を使うのが一般的です。プロパティはフィールドと同じように値を読み書きできる書き方ですが、`get`だけを書けば「作ったあとは書き換えられない」という制限を付けられます。

```csharp
var product = new Product("コーヒー", 480);
Console.WriteLine($"{product.Name}: {product.Price}円");

public class Product
{
    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }

    public string Name { get; }
    public decimal Price { get; set; }
}
```

```
コーヒー: 480円
```

`Product`のコンストラクタが`name`と`price`を受け取り、それぞれ`Name`と`Price`というプロパティに代入しています。`Name`は`get`だけなので、コンストラクタの中でしか値を決められません。`Price`は`get; set;`なので、あとから値段を変更できます。

- 生成したあと絶対に変えたくない値は、コンストラクタで受け取り`get`だけのプロパティにする
- 生成したあとに変わる可能性がある値だけ、`set`も付ける

## よくある間違い

### 代入すると別のインスタンスができると思い込む

クラスの変数を別の変数に代入しても、新しいインスタンスが作られるわけではありません。同じインスタンスを2つの変数が指すようになるだけなので、片方のフィールドを書き換えると、もう片方の値も変わって見えます。「コピーしたつもりが元のデータまで変わっていた」という形でつまずきやすい間違いです。

```csharp
// NG: b への代入のつもりが a まで変わる
var a = new Product("コーヒー", 480);
var b = a;
b.Price = 600;
Console.WriteLine(a.Price);

public class Product
{
    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }

    public string Name { get; }
    public decimal Price { get; set; }
}
```

```
600
```

```csharp
// OK: 別のインスタンスが欲しいときは new でもう1つ作る
var a = new Product("コーヒー", 480);
var b = new Product(a.Name, 600);
Console.WriteLine(a.Price);

public class Product
{
    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }

    public string Name { get; }
    public decimal Price { get; set; }
}
```

```
480
```

### getだけのプロパティに、あとから代入できると思い込む

プロパティを`get`だけにすると、その値を決められるのはコンストラクタの中だけになります。インスタンスを作ったあとで値を変更しようとすると、コンパイルエラーになります。

```csharp
// NG: Name は get だけなので、あとから代入できない
var product = new Product("コーヒー", 480);
product.Name = "紅茶";

public class Product
{
    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }

    public string Name { get; }
    public decimal Price { get; set; }
}
```

```
CS0200: プロパティまたはインデクサー 'Product.Name' は読み取り専用であるため、割り当てることはできません
```

```csharp
// OK: set も付けたプロパティだけを、あとから変更する
var product = new Product("コーヒー", 480);
product.Price = 520;
Console.WriteLine($"{product.Name}: {product.Price}円");

public class Product
{
    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }

    public string Name { get; }
    public decimal Price { get; set; }
}
```

```
コーヒー: 520円
```

## 用語まとめ

| 用語 | 意味 |
|---|---|
| クラス | データと処理をひとつにまとめて名前を付けた設計図 |
| インスタンス | クラスをもとに`new`で実際に作った実体 |
| フィールド | クラスの中に直接値を持たせる変数 |
| プロパティ | `get`と`set`を使って、フィールドのように値を読み書きする書き方 |
| コンストラクタ | `new`でインスタンスを作るときに自動的に呼ばれる、初期化専用の処理 |
| 既定のコンストラクタ | コンストラクタを自分で書かなかったときに自動的に用意される、何もしない引数なしのコンストラクタ |
