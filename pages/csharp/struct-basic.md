## この記事でわかること

- structを使って、複数の値をひとつにまとめた型が書ける
- structへの代入や引数渡しで値がコピーされる、という挙動を説明できる
- structの`==`とEqualsで挙動が違う理由を説明できる
- structとclassのどちらを使うべきか、判断基準を説明できる

## 一言でいうと

structは、複数の値をひとつのまとまりとして扱うための型です。ただしclassと違い、変数に入れたり別の場所に渡したりすると、中身がまるごと複製されるという特徴があります。

宅配便の伝票を思い浮かべてください。伝票をコピーして別の人に渡すと、渡された側は自分だけの伝票を手にします。その伝票に書き込んでも、元の伝票の中身は変わりません。プログラムの世界でも、structの値を別の変数に代入すると、それぞれが独立した実体になり、片方を書き換えてももう片方には影響しません。ただし、実際の伝票のコピーには手間がかかりますが、structのコピーはコンピュータの中で一瞬で行われます。

## どんなときに困るのか

座標を表す`Point`をメソッドに渡し、そのなかでX座標を書き換えたつもりが、呼び出し元の`Point`の値はまったく変わっていなかった、という場面があります。classのつもりで扱っていると、これは「値が勝手に元に戻った」ように見えて混乱します。

反対に、classと同じ感覚でプロパティ経由のstructの中身を直接書き換えようとして、見慣れないコンパイルエラーに出会うこともあります。structが値型であることを知らないと、こうした挙動の理由が分からず、原因探しに時間を使うことになります。

structの挙動を理解していれば、値がコピーされることを前提に設計でき、こうした混乱を避けられます。

## 動かしてみる

```csharp
var p1 = new Point(1, 2);
var p2 = p1;
p2.X = 100;

Console.WriteLine(p1.X);
Console.WriteLine(p2.X);

struct Point
{
    public int X;
    public int Y;

    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }
}
```

```
1
100
```

`p2 = p1`のところで、`p1`の値がそのまま`p2`にコピーされます。この時点で`p1`と`p2`は別々の実体になっているので、続けて`p2.X = 100`としても`p1.X`は影響を受けず、`1`のままです。もし`Point`がclassだったら、`p1`と`p2`は同じインスタンスを指すため、`p2.X`を変えると`p1.X`も`100`になっていました。

## 仕組み

structは値型です。「参照型と値型のメモリモデル」で説明した通り、値型の変数は値そのものを保持し、代入すると値がコピーされます。structは、この値型を自分で定義するための構文です。フィールド・プロパティ・コンストラクタの書き方は「クラス(class)の基本」で説明したものとほとんど同じですが、structで定義した型はclassと違って値型になります。

先ほどの`Point`の例は、まさにこの値型の性質そのものです。代入や引数渡しのたびにstructの値がコピーされ、コピーされた後にどちらかの値を変更しても、もう一方には影響しません。

- 変数に代入したり、引数としてメソッドに渡したりするたびに、structの値はコピーされる
- コピーされた値を変更しても、コピー元の値は変わらない
- コンストラクタを自分で定義する場合は、そのなかですべてのフィールドに値を設定する
- structには既定でフィールドの値を比較するEqualsが用意されているが、`==`演算子は自動的には使えない

## 実務での使い方

structは、座標や金額、IDのように「小さくて、コピーされても困らない値」を表すのに向いています。

```csharp
var price = new Money { Amount = 1000, Currency = "JPY" };
Console.WriteLine($"{price.Amount}{price.Currency}");

public struct Money
{
    public decimal Amount { get; init; }
    public string Currency { get; init; }
}
```

```
1000JPY
```

`Money`のように、一度作ったら値を変えない小さなデータをまとめるとき、structはよい選択になります。使い分けに迷ったときは、次の基準で考えてみてください。

- 座標・金額・IDのように、フィールド数が少なく値そのものを表すデータならstructを検討する
- 複数箇所で同じインスタンスを共有し、どこかで変更したら他の場所にも反映したいデータならclassを使う

## よくある間違い

### プロパティ経由でstructの中身を直接書き換えようとする

structを保持するプロパティに対して、そのフィールドを直接書き換えようとすると、コンパイルエラーになります。これは、プロパティの`get`が返すのが一時的なコピーであり、そのコピーに対する書き換えには意味がないとコンパイラが判断するためです。

```csharp
// NG: プロパティ経由のstructは一時的なコピーになるため書き換えられない
var box = new Box { Position = new Point { X = 0, Y = 0 } };
box.Position.X = 10;

public struct Point
{
    public int X;
    public int Y;
}

public class Box
{
    public Point Position { get; set; }
}
```

```
error CS1612: 変数ではないため、'Box.Position' の戻り値を変更できません
```

```csharp
// OK: 新しい値をまるごと作り直して代入する
box.Position = new Point { X = 10, Y = box.Position.Y };
```

### `==`で比較できると思い込む

structには既定でEqualsが用意されており、フィールドの値が同じかどうかを比較できます。ところがEqualsがあるからといって`==`演算子も使えるとは限りません。structでは`==`を自分で定義しない限り使えないため、うっかり使うとコンパイルエラーになります。

```csharp
// NG: structでは==演算子を自分で定義しないと使えない
var p1 = new Point { X = 1, Y = 2 };
var p2 = new Point { X = 1, Y = 2 };

if (p1 == p2)
{
    Console.WriteLine("同じ");
}

public struct Point
{
    public int X;
    public int Y;
}
```

```
error CS0019: 演算子 '==' を 'Point' と 'Point' 型のオペランドに適用することはできません
```

```csharp
// OK: Equalsメソッドで比較する
if (p1.Equals(p2))
{
    Console.WriteLine("同じ");
}
```

## 用語まとめ

| 用語 | 意味 |
|---|---|
| struct | 複数の値をひとつにまとめて扱うための、値型のカスタム型 |
| 値のコピー | 変数に代入したり引数として渡したりするときに、値そのものが複製されること |
| Equals | 2つの値の中身が等しいかどうかを判定するメソッド |
